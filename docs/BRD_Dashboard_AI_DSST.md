## 1. ภูมิหลังและวัตถุประสงค์

### 1.1 ภูมิหลัง
ตลาดงานสาย AI, Data Science และ Statistics ขยายตัวต่อเนื่อง (เช่น BLS คาดการณ์การจ้างงาน data scientist โต 34% ช่วง 2024–2034) ขณะที่หลักสูตรในสถาบันการศึกษาแตกต่างกันทั้งชื่อ เนื้อหา และทักษะที่สอน ผู้กำหนดนโยบาย อาจารย์/ผู้บริหารหลักสูตร และนักศึกษา ยังไม่มีเครื่องมือเดียวที่เปรียบเทียบ "สิ่งที่ผลิต" กับ "สิ่งที่ตลาดต้องการ" ได้

### 1.2 คำถามทางธุรกิจ (Business Questions)
| รหัส | คำถาม | Tab |
|---|---|---|
| BQ1 | มีคนจบเท่าไร จากหลักสูตรไหน และเรียนทักษะอะไรมา | Tab 1 |
| BQ2 | ตลาดจ้างงานเท่าไร ต้องการทักษะอะไร บริษัทไหนรับ เงินเดือนเท่าไรในแต่ละระดับ | Tab 2 |
| BQ3 | ทักษะที่เรียนกับทักษะที่ตลาดต้องการต่างกันตรงไหน (Skill Mismatch) | Tab 3 |

### 1.3 วัตถุประสงค์เชิงธุรกิจ
1. แสดงภาพรวมอุปทาน (บัณฑิต) และอุปสงค์ (ตำแหน่งงาน) ในมุมมองเดียวกัน
2. ชี้ช่องว่างทักษะที่ตรวจสอบย้อนกลับได้ถึงรายวิชาและประกาศงานต้นทาง
3. ให้ผู้ใช้กรองครั้งเดียวแล้วทุกกราฟใน tab อัปเดตตามกัน (cross-filter)

### 1.4 ตัวชี้วัดความสำเร็จ
- ผู้ใช้ตอบ BQ1–BQ3 ได้ภายใน 3 คลิก โดยไม่ต้องอ่านเอกสารประกอบ
- ทุกตัวเลขบน dashboard คลิกดู "แหล่งข้อมูล/ปีที่อัปเดต/license" ได้
- เวลาตอบสนองเมื่อเปลี่ยนตัวกรอง ≤ 2 วินาทีที่ข้อมูลระดับที่ระบุใน §8

## 2. ขอบเขต

### 2.1 In scope
- Web dashboard 3 tab ตามหัวข้อ BQ1–BQ3
- Data pipeline (ดึง–ทำความสะอาด–จับคู่ทักษะ–จัดเก็บ) จากแหล่ง open data
- ครอบคลุมประเทศไทยเป็นหลัก (Tab 1) และตลาดงานทั่วโลก/กรองประเทศได้ (Tab 2) — ประเทศไทยแสดงเป็นลำดับแรกเมื่อมีข้อมูล

### 2.2 Out of scope (เฟสนี้)
- การพยากรณ์ตลาดงานด้วยโมเดล ML
- การดึงข้อมูลจากแหล่งที่ไม่ใช่ open data (Lightcast, LinkedIn Talent Insights, Glassdoor ฯลฯ)
- ระบบล็อกอิน/ข้อมูลส่วนบุคคลของนักศึกษารายคน (ใช้ข้อมูลสรุปเท่านั้น)
- แอปมือถือ (รองรับ responsive ในเบราว์เซอร์เท่านั้น)

### 2.3 สมมติฐาน
- นิยาม "สาย AI/DS/Stat" = หลักสูตรและอาชีพที่จับคู่ได้กับ CIP 11.0102, 30.7001, 30.7101, 27.0501 และ SOC 15-2051, 15-2041, 15-1221 (ปรับได้ใน config)
- ปีข้อมูลมาตรฐานเริ่มต้น: ปีการศึกษา 2561–ล่าสุด (ไทย), 2023–ล่าสุด (ตลาดงาน)

## 4. ความต้องการด้านข้อมูล (Data Requirements)

### 4.1 แผนผังแหล่งข้อมูล → ฟีเจอร์
| ข้อมูลที่ dashboard ต้องใช้ | แหล่งที่มีแล้ว (ดู `datasets/`) | ช่องว่าง |
|---|---|---|
| จำนวนผู้จบรายปี (ระดับกลุ่มสาขา) | MHESI/data.go.th (ไทย), IPEDS (สหรัฐฯ), Eurostat | ⚠️ **รายหลักสูตรของไทยยังไม่มีชุดเปิดที่ยืนยันแล้ว** |
| ชื่อหลักสูตร/สถาบัน | พอร์ทัล MHESI `info.mhesi.go.th`, TCAS/เว็บมหาวิทยาลัย | ⚠️ ต้องตรวจ license และวิธีดึง |
| รายวิชาบังคับต่อหลักสูตร | มคอ.2 / เว็บหลักสูตรของมหาวิทยาลัย (เอกสารสาธารณะ) | ⚠️ ไม่มี dataset กลาง — ต้องรวบรวม/ถอดข้อมูลเอง (manual/semi-auto) |
| บัณฑิตมีงานทำปีที่ 1/2/3 หลังจบ | ผลสำรวจภาวะการมีงานทำของบัณฑิต (อว./สถาบัน) | ⚠️ ไม่พบชุดเปิดที่ติดตามรายปีต่อเนื่อง 3 ปี — ดูข้อ 4.2 |
| ค่าเทอม | เว็บมหาวิทยาลัย/TCAS | ⚠️ ไม่มี dataset กลาง ต้องรวบรวม |
| ตำแหน่งงานว่าง/ปริมาณจ้างงาน | BLS OEWS/Projections, ประกาศงาน (Kaggle, OECD.AI), Eurostat | ⚠️ ประกาศงานไทยแบบ open ยังไม่พบ |
| ทักษะที่ตลาดต้องการ | O*NET Technology Skills, ESCO, ประกาศงาน | license ของชุด Kaggle ต้องยืนยัน |
| บริษัทที่รับ | Companies House, DBD (ระดับสรุป), Epoch AI, ประกาศงาน | ชื่อบริษัทที่ "รับงาน AI จริง" ต้องกรองจากประกาศงาน |
| เงินเดือนตามระดับ | ai-jobs.net (CC0), BLS, Stack Overflow Survey | เงินเดือนไทยเปิดมีน้อย ใช้ proxy ตามประเทศที่เลือก |

### 4.2 ช่องว่างข้อมูลสำคัญและแนวทาง (ต้องตัดสินใจก่อนพัฒนา)
1. **บัณฑิตมีงานทำปี 1/2/3:** หากไม่มีข้อมูลติดตามจริง ให้เลือกหนึ่งในสามทางและระบุบน dashboard ให้ชัด
   - (ก) ใช้ผลสำรวจภาวะการมีงานทำ (snapshot ปีเดียวต่อรุ่น) แล้วแสดงเป็น cohort ที่เก็บได้
   - (ข) ขอข้อมูลสรุปจากสถาบัน/หน่วยงาน (ต้องมี MOU/ข้อตกลง)
   - (ค) แสดงข้อมูลตัวอย่าง (synthetic) พร้อมป้าย "ตัวอย่างข้อมูล" เพื่อพัฒนา UI ก่อน — **ห้ามแสดงเป็นข้อมูลจริง**
2. **รายวิชาและค่าเทอม:** เฟสแรกรวบรวมจาก 10–20 หลักสูตรเป้าหมายด้วยมือ/สคริปต์ แล้วเก็บใน `curriculum.csv` พร้อมลิงก์ต้นทางและวันที่เก็บ
3. **การดึงข้อมูลจากเว็บ:** ตรวจ robots.txt และเงื่อนไขการใช้ก่อนดึงอัตโนมัติ

### 4.3 โมเดลข้อมูล (Logical Data Model)
- `program`(program_id, ชื่อหลักสูตร TH/EN, สถาบัน, ระดับ, สาขา CIP/ISCED, ประเภท AI/DS/Stat, ค่าเทอมต่อภาคและตลอดหลักสูตร, source, as_of)
- `graduates`(program_id, year, count, level)
- `course`(course_id, program_id, ชื่อวิชา, หน่วยกิต, บังคับ/เลือก, คำอธิบายวิชา)
- `course_skill`(course_id, skill_id, ความมั่นใจการจับคู่)
- `employment_outcome`(program_id หรือกลุ่มสาขา, cohort_year, years_after_grad ∈ {1,2,3}, n_employed, n_total, in_field_flag, source)
- `job_posting`(posting_id, ตำแหน่ง, บริษัท, ประเทศ, ระดับ, วันที่, เงินเดือน USD, source)
- `posting_skill`(posting_id, skill_id)
- `skill`(skill_id, ชื่อมาตรฐาน, หมวด, alias, รหัส O*NET/ESCO)
- `salary_benchmark`(ประเทศ, ระดับ, p25, median, p75, ปี, source)
- `company`(company_id, ชื่อ, ประเทศ, ประเภทธุรกิจ/SIC, จำนวนประกาศ)

### 5.2 Tab 1 — ปริมาณบัณฑิตและทักษะที่เรียนมา (BQ1)
| รหัส | กราฟ | ข้อมูล / การโต้ตอบ | Plotly |
|---|---|---|---|
| T1-C1 | **หลักสูตรที่ผลิตบัณฑิตสาย AI/DS/Stat และจำนวนต่อปี** | แกน X = ปี, แกน Y = จำนวนบัณฑิต, ซีรีส์ = หลักสูตร/สถาบัน; มี toggle เลือกแสดง Top-N, ระดับปริญญา; คลิกซีรีส์/แท่ง = เลือกหลักสูตร (และปี) | stacked bar / line + ตารางจัดอันดับ |
| T1-C2 | **รายวิชาบังคับของหลักสูตรที่ตรงกับสายงาน** | แสดงรายวิชาบังคับของหลักสูตรที่เลือกจัดกลุ่มตามทักษะ (สถิติ, ML, โปรแกรมมิ่ง, data eng, ฯลฯ) พร้อมหน่วยกิตและสัดส่วนที่ตรงกับสายงาน; ไม่เลือกหลักสูตร = รวมทุกหลักสูตรตามตัวกรอง | treemap / sunburst หรือ horizontal bar |
| T1-C3 | **บัณฑิตที่ได้งานปีที่ 1, 2, 3 หลังจบ** | สัดส่วน/จำนวนที่มีงานทำ (และงานตรงสาย) ที่ 1, 2, 3 ปี; แยกตามหลักสูตร/รุ่น; ต้องระบุ n และแหล่งข้อมูลของ cohort | grouped bar หรือ line + CI |
| T1-C4 | **ค่าเทอม** | ค่าเทอมต่อภาคและตลอดหลักสูตรของหลักสูตรที่เลือก/ตามตัวกรอง; มี scatter "ค่าเทอม vs อัตรามีงานทำ" (bubble = จำนวนบัณฑิต) | bar + scatter/bubble |
| T1-KPI | แถบ KPI: จำนวนหลักสูตร, บัณฑิตรวม, % มีงานทำใน 1 ปี, ค่าเทอมมัธยฐาน | อัปเดตตามตัวกรอง | indicator/cards |

**พฤติกรรม cross-filter ของ Tab 1 (ตัวอย่าง):** คลิกหลักสูตร "วท.บ. วิทยาการข้อมูล – มหาวิทยาลัย X" ใน T1-C1 → T1-C2 แสดงรายวิชาบังคับของหลักสูตรนั้น, T1-C3 แสดงอัตรามีงานทำของหลักสูตรนั้น, T1-C4 ไฮไลต์ค่าเทอมของหลักสูตรนั้น; คลิกวิชากลุ่ม "Machine Learning" ใน T1-C2 → กราฟอื่นกรองเหลือหลักสูตรที่มีวิชากลุ่มนี้

| T2-KPI | ตำแหน่งรวม, เงินเดือนมัธยฐานระดับเริ่มต้น, จำนวนบริษัท, ทักษะอันดับ 1 | อัปเดตตามตัวกรอง | cards |

**พฤติกรรม cross-filter ของ Tab 2:** คลิกแท่งทักษะ "SQL" → T2-C1 เหลือประกาศที่ต้องการ SQL, T2-C3 แสดงบริษัทที่ต้องการ SQL, T2-C4 แสดงเงินเดือนของตำแหน่งที่ต้องการ SQL; คลิก box ระดับ "ปานกลาง" → ทุกกราฟกรองเฉพาะระดับนี้

### 5.4 Tab 3 — Skill Mismatch (BQ3)
| รหัส | กราฟ | ข้อมูล / การโต้ตอบ | Plotly |
|---|---|---|---|
| T3-C1 | **Supply vs Demand ต่อทักษะ** | แต่ละทักษะ: ความต้องการ (D) เทียบความครอบคลุมในหลักสูตร (S) | diverging bar / dumbbell |
| T3-C2 | **Gap matrix** | แถว = ทักษะ, คอลัมน์ = ระดับงาน หรือ หลักสูตร; สี = ขนาด gap | heatmap |
| T3-C3 | **Quadrant ทักษะ** | X = ความครอบคลุมในหลักสูตร, Y = ความต้องการตลาด; ควอแดรนต์: ขาดแคลน (สูง–ต่ำ), สมดุล, ผลิตเกินความต้องการ (ต่ำ–สูง), ไม่เกี่ยวข้อง | scatter + เส้นแบ่ง |
| T3-C4 | **ตารางข้อเสนอแนะ** | ทักษะที่ gap สูงสุด พร้อมวิชาที่เกี่ยวข้องในหลักสูตรและตัวอย่างประกาศงาน (drill-down) | table |
| T3-C5 | **เปรียบเทียบหลักสูตร** | Mismatch score รายหลักสูตร จัดอันดับ | bar |

#### นิยามตัวชี้วัด (ฉบับร่าง — ต้องตกลงกับ stakeholder)
- **Demand share** D(s) = ประกาศงานที่ระบุทักษะ s ÷ ประกาศงานทั้งหมดใน filter (0–1)
- **Supply coverage** S(s) = Σ ผู้จบจากหลักสูตรที่มีวิชาบังคับ map กับทักษะ s ÷ ผู้จบทั้งหมดใน filter (ถ่วงน้ำหนักด้วยจำนวนบัณฑิต; ทางเลือก: ถ่วงด้วยหน่วยกิต)
- **Gap** G(s) = D(s) − S(s) → บวก = ขาดแคลน, ลบ = ผลิตเกิน
- **Mismatch score ของหลักสูตร** = Σ_s w(s)·max(0, D(s) − c(p,s)) ÷ Σ_s w(s)·D(s), โดย c(p,s) = ทักษะ s ครอบคลุมในหลักสูตร p (0/1 หรือเศษส่วนตามหน่วยกิต), w = น้ำหนักตามความสำคัญ (ค่าเริ่มต้น = 1)
- ข้อจำกัดที่ต้องแสดงบน dashboard: ทักษะที่ "สอนในวิชา" ≠ ทักษะที่ "ได้จริง"; ประกาศงานไม่ใช่จำนวนงานที่จ้างจริง

**ตัวกรองข้ามกราฟ Tab 3:** เลือกระดับงานหรือหลักสูตรเดียว → ทุกกราฟคำนวณ D และ S ใหม่ภายใต้ filter นั้น; คลิกทักษะ → แสดงวิชาและประกาศที่เกี่ยวข้องใน T3-C4

### 6.1 หลักการ Cross-filter
- เก็บ `filter-state` เป็น `dcc.Store` กลางต่อ tab (dict ของ dimension → ค่าที่เลือก)
- ทุกกราฟเป็น callback ที่อ่าน `filter-state` และข้อมูลแล้ววาดใหม่; การคลิกกราฟเขียนกลับ `filter-state` (กราฟต้นทางไฮไลต์การเลือกแทนการกรองตัวเองทิ้ง เพื่อไม่ให้กราฟหาย)
